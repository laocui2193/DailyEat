项目名称：随心吃吃 —— 桌面餐厅推荐工具（前后端全栈 + AI Agent）
项目时间：2026.07 — 2026.10
担任角色：独立开发（产品设计 / UI 设计 / 前端 / 后端 / 数据库 / AI Agent / 打包分发）
技术栈：Electron、原生 HTML/CSS/JavaScript、Python、Flask、SQLite、多模型 LLM API（DeepSeek v4-pro/flash、硅基流动视觉与 embedding，OpenAI 兼容）、electron-builder

【项目描述】
面向香港大学学生的 Windows 桌面应用，每日自动推荐 3 家周边餐厅，
解决"今天吃什么"的选择困难。内置 623 家全港餐厅数据（含 47 家米其林
星级、亚洲50最佳、458 家餐厅周优惠，数据来自人工调研、权威榜单与
官方 API 自动导入三条通道），自建用户/评分/排行榜后端与 AI Agent
推荐引擎，从需求分析、产品设计、前后端开发、数据库设计到打包分发
全流程独立完成。

【核心工作】
1. 推荐算法与筛选系统：复合筛选链——近 3 天去重、菜系去重、14 大类
   两级口味偏好、用餐时段自动识别、预算上下限双滑块（对数刻度设计，
   低端密集高端拉开）、「无需预约」独立开关，四维筛选可任意叠加；
   支持午夜自动刷新、手动刷新与运营侧每日精选人工指定

2. 数据架构：餐厅数据与代码分离（restaurants.json），实现「远程拉取 →
   本地文件 → localStorage 缓存」三级降级加载；版本控制 + 数据迁移
   保护（数据集变更时自动清理失效记录）；米其林星/绿星/预约标签由
   数据字段驱动，全部用内联 SVG 手绘徽章（6 花瓣旋转近似星形、三叶草）

3. 自建后端（Python + Flask + SQLite）：设计并实现 REST API——用户系统
   （注册/登录/会话 token）、评分评论（一用户一店一条、可改分）、
   排行榜（SQL 聚合查询：GROUP BY + AVG + HAVING 防刷分）、收藏云同步
   （登录时本地/云端自动合并）、打卡签到（连续天数计算）、UGC 餐厅
   提交（审核制工作流）；前端离线自动降级，后端不可用时本地功能不受影响

4. AI Agent 开发：从零实现 LLM Agent——Tool Calling（函数调用协议：
   JSON Schema 工具定义 + 工具消息回填）、ReAct 多步推理循环（思考
   →调工具→观察→再思考，防死循环限制 + 工具并行执行）、SSE 流式输出、
   可写工具 Human-in-the-loop 确认机制（服务端会话暂停/恢复）；
   多模型分工——主推理 deepseek-v4-pro、事实核查与蒸馏用便宜模型
   deepseek-flash（评审异步化：卡片先出、核查后台修正）；幻觉防治三层
   体系——防幻觉提示词铁律 + 评审 Agent 事实核查 + 幻觉专项评测用例；
   三层记忆体系——会话历史（多轮上下文）、用户画像（评分/收藏/打卡
   聚合）、偏好蒸馏（对话结束后 LLM 抽取长期偏好存 SQLite，下次对话
   自动注入系统提示词，实现跨对话记忆）；RAG 语义搜索（embedding
   向量化 + 余弦相似度，支持「像XX那样的店」）；多模态识图（上传食物
   照片 → Qwen3-VL 视觉模型识别菜名 → 注入 Agent 上下文推荐餐厅）；
   性能调优——思维链禁用（发现旗舰模型默认思考 6 秒才出正文）、查询
   缓存（重复提问秒回）、流式进度事件设计；
   用 LLM 批量数据增强解决关键词搜索的语义鸿沟（622 家餐厅生成 16 维
   场景特征标签，"海景"可命中简介写"维港景色"的餐厅）；
   OpenAI 兼容接口可配置任意模型服务商，密钥服务端存储

5. 个性化画像：结合收藏、推荐历史、评分记录三类行为信号加权分析，
   生成用户口味人格标签与偏好分布可视化（纯前端计算）

6. 安全实践：密码 pbkdf2 加盐哈希存储（数据库中无明文）、随机 token
   会话凭证（每次登录轮换）、参数化查询防 SQL 注入、接口输入校验
   （长度/范围/唯一性）、未认证请求 401 拦截、审核接口管理员密钥鉴权

7. 数据库演进：数据层抽象设计（insert/find/update 接口），支撑存储
   引擎从 JSON 文件平滑迁移至 SQLite（上层业务代码零改动），并完成
   存量数据无损迁移

8. 桌面端与工程化：Electron 窗口/托盘/主题管理，卡片错峰入场动画、
   午夜倒计时等交互细节；electron-builder 打包绿色版并分发测试，
   排查解决 Windows 符号链接权限、ELECTRON_RUN_AS_NODE 环境变量等
   打包环境问题

【技术难点】
· Agent 正确性工程：手写 ReAct 工具调用循环——防死循环硬上限、流式
  tool_calls 增量分片组装、提示词调优（抑制 LLM 对失败搜索的无效重试、
  工具调用预算控制、融合菜系精确匹配 vs 泛搜的语义陷阱）；幻觉防治——
  防幻觉提示词铁律 + 双模型评审（便宜模型事实核查主模型输出，异步化
  不阻塞响应）+ 幻觉专项评测用例
· 流式 UI 状态管理：SSE 事件流下的界面状态——思考过程按需求全部隐藏
  （独立元素动画避免重绘打断）、卡片先出评审后台修正、多弹窗栈式叠加
  （AI 对话上开详情，关闭回到对话层）
· 写操作安全设计：Agent 执行类工具采用 Human-in-the-loop 确认机制——
  服务端暂停循环并保存会话状态 → 前端确认弹窗 → 确认后恢复执行，
  实现"AI 可以建议、人类才能决定"的安全边界
· 网页转 API + 数据清洗：官网为 JS 渲染空壳（仅 2KB 骨架），通过
  DevTools 挖出官方裸接口并分页导入 419 家餐厅；用 LLM 批量完成
  字段补全、废弃条目清洗（"(don't use)"标记）、菜系标签细化——发现
  227 家餐厅共用大类名导致推荐算法菜系去重碰撞（单店平均 300 天才
  轮到一次），细化为 208 种具体菜系后消除稀释
· 推荐系统验证：复刻推荐算法做蒙特卡洛模拟（3 随机种子 × 3 万次
  推荐），证明全量合格餐厅 100% 可达（零遗漏）；建立 21 用例的 Agent
  评测集实现一键回归，断言从"写死餐厅 id"演进为"特征断言 + 禁止断言"
  三层体系，支撑提示词与数据的安全迭代
· 数据语义鸿沟：关键词搜索无法命中"海景"≈"维港景色"的语义等价，
  通过 LLM 批量生成 16 维场景特征标签（622 家全覆盖）解决
· 模型服务陷阱：deepseek-chat 模型名被服务商静默迁移到 flash 弱模型，
  请求与响应模型不一致——通过实测响应字段定位，切换旗舰模型并建立
  多模型分工；旗舰模型默认思维链模式每次调用先思考 6 秒才出正文，
  通过 thinking: disabled 参数优化响应速度
· 环境变量陷阱：ELECTRON_RUN_AS_NODE 会话级注入导致 App 以 Node 模式
  闪退——Windows 环境变量「置空」与「真删除」的语义差异排查

【项目亮点】
· 全栈闭环 + Agent 工程：独立完成「产品 → 前端 → 后端 → 数据库 →
  AI Agent → 打包分发」完整链路；Agent 全程手写零框架（协议层吃透
  Function Calling 与 SSE 流式），前端零依赖、后端单依赖（Flask），
  技术选型有明确取舍
· 数据产品思维：三条数据通道（人工调研 / 权威榜单 / 官方 API 自动
  导入）+ 幂等流水线实现"数据自扩张"——每次活动重跑脚本即自动更新
  优惠、自动入库新餐厅，数据库从 85 家增长至 623 家
· 真实场景驱动：功能迭代（预算筛选、预约提示、云端评分、AI 推荐）
  均由真实使用反馈推动；评测集的设计原则（断言能力而非断言数据）也
  源于一次真实误推荐的教训
· 架构演进：随需求增长完成「纯静态 → 数据外部化 → 自建后端+数据库 →
  AI Agent 化」四阶段升级，每次升级都有明确的性能/体验动机
